# ccj — 简历向项目总结

> 一个从零手写的编码 Agent 运行时（Java 21）：一条核心循环同时驱动终端 REPL、单次运行与浏览器控制台，
> **四种协议**流式对接（OpenAI chat-completions / Anthropic Messages / Responses / Gemini），除 Jackson 外
> 不引入任何框架——HTTP 服务、SSE 解析与广播、JSONL 会话存储、上下文预算、命令行解析、Prometheus 指标、
> 离线评测与语义检索全部自己实现。

## 一、可直接粘贴的简历条目

**oh-my-ccj · 个人项目 | Java 21 · 2026**
- 从零实现编码 Agent 运行时（**27.3k 行主代码 / 115 个文件 / 884 个测试 / 单一运行时依赖**）：核心循环 + 工具系统 +
  双协议流式 Provider + 零框架 Web 控制台，覆盖流式增量解析、工具审批与取消、上下文预算、中断历史修复、
  多工作区与会话级用量统计。
- 手写 **SSE 增量解码器与两种厂商协议的流式组装**（按 `index` 重组被任意字节边界切开的 tool_call 分片、
  UTF-8 边界安全、断流补齐、扩展思考块带签名回传），并为「HTTP 200 但返回的不是事件流」这类静默失败设计了可诊断的错误路径。
- 设计了 **上下文预算**（`ContextBudget`）：超预算时先抹掉旧工具输出（保留 call/result 配对，wire 仍合法）、
  再整段丢弃最旧的对话轮次、最后截断当前轮次里最大的结果并显式标注，且用属性测试覆盖「任何投影都不能把
  assistant 的调用和它的结果拆开」这一协议不变量；会话文件保持完整，只对单次请求做投影。
- 设计并实现**可取消的工具执行**与**只读工具并发**：abort 会杀掉正在跑的 shell 进程树（而不是等它的超时），
  同一回合连续的只读工具用虚拟线程并发执行、结果仍按模型请求的顺序落盘。
- 自研无构建步骤的浏览器控制台（`com.sun.net.httpserver` + 虚拟线程 + 手写事件广播与背压队列）：**一个停止读取的
  SSE 客户端曾能阻塞整个 Agent 回合**，用「每连接有界队列 + 由连接线程独占写 socket」修复，并以
  「旧版本卡死 45s / 新版本正常跑完」的前后对比脚本验证；浏览器实测又揪出「回合结束后界面永久卡在运行中、
  静默吞掉下一条消息」的竞态（POST 返回后才置忙，而快速回合早已渲染完 `done`），并同时修掉了服务端事件顺序与客户端自愈逻辑。
- 实现了**自举（self-bootstrap）**：agent 能改自己的源码、构建、并把自己换掉。三条硬事实决定了它不是一句
  `mvn package && exec java -jar`：构建会**截断正在被 JVM 执行的 jar**（截断一个 mmap 的 jar 会在构建中途杀掉
  那个进程，报一个完全不提原因的 `NoClassDefFoundError`）；**rename 是安全的**（换的是目录项，运行中的进程继续用它
  已经打开的 inode）；**进程不能替换自己的代码**。于是构建写到 scratch 名字、原子 rename 覆盖、进程以 75
  （`EX_TEMPFAIL`）退出，由启动器启动新 jar；一次性 `-p` 不会被重新发起，连续两次重启会停下让人看一眼。
- 工程化：**884 个测试 / 92 个类**（含真实 `CLI → HTTP → SSE → 工具 → 磁盘` 端到端；Provider 单测的服务端按 19 字节
  分片发送以证明分帧重组，端到端服务端则按长度切三段），默认拒绝的审批门、token 门与 Host 白名单（防 DNS rebinding）、请求体上限、路径穿越白名单、
  基于真实路径的软链接逃逸检测。

**技术栈**：Java 21（record / sealed / 模式匹配 switch / 虚拟线程 / text block）、`java.net.http`、Jackson、
JUnit 5、原生 Web（ES2020 + CSS 变量主题，无框架无构建）、Maven。

## 三、技术亮点（每条都是「问题 → 做法 → 结果」）

### 1. 双协议流式解析：把「网络会怎么坏」当成需求
- **问题**：SSE 帧会落在任意字节边界上；tool_call 的参数是字符串分片；服务端可能返回 200 但body 是
  JSON 错误页；网关会省略 `index`。
- **做法**：手写 `Sse` 增量解码（多行 data 合并、CRLF、注释帧、`[DONE]`、尾帧不丢）；OpenAI 侧按 `index`
  维护 `ToolCallBuffer`（`TreeMap`，保证乱序到达仍按 wire 顺序产出），Anthropic 侧按 `index` 维护内容块表；
  **没有事件帧的 2xx 响应不再被当成「空回答」，而是抛出带响应摘要的错误**。
- **结果**：两个协议的解析器都被「19 字节分片的流」测试钉死；一个静默失败（上游挂了却显示成功空回合）
  变成了可读报错；截断的 tool 参数不再让整个会话永久无法发送。

### 2. 核心循环：无步数上限、可中断、故障隔离
- **问题**：模型可能幻觉工具名、给错 JSON、陷入循环；用户可能中途叫停。而「能中断」和「中断后还能继续」在
  很多实现里是互斥的——中断恰好落在「assistant 已落盘、工具结果未落盘」的窗口里，会话就永久废了。
- **做法**：`sealed interface Message`（System/User/Assistant/ToolResult）描述对话而不描述厂商协议；
  工具参数**保持原始 JSON 文本**，核心层不解析——厂商负责序列化、工具自己解析，因此一个畸形参数只会变成
  一条错误结果，而不是污染整个会话；**刻意不设步数上限**（上限分不清「模型卡住」和「任务很长」，砍错的代价
  是让一次本来会成功的运行失败），改用 `AtomicBoolean` 协作式中断 + 每条消息即时落盘。
- **结果**：未知工具名 / 非法参数 / 工具抛异常全部转为模型可读的错误结果，会话继续；abort 在「步骤之间」与
  「每个工具调用之前」生效；`Ctrl-C` 后会话仍可用 `--resume` 打开，**且中断本身不会留下无法继续的会话**
  （见第 6 节）。

### 3. 零框架 Web 控制台 + SSE 广播的背压设计
- **问题**：`com.sun.net.httpserver` 默认单线程执行器（一个 SSE 流会冻住所有请求）；事件扇出若直接写
  socket，一个停止读取的标签页会把发布事件的**回合线程**连同全局重放锁一起挂死。
- **做法**：缓存线程池 + 一个 `/` 上下文路由；事件先入**每连接有界队列**（4096），由该连接自己的线程
  独占写 socket 并按 15s 心跳；队列溢出则丢弃该客户端（页面重连后重新拉 `/api/history`）；重连只需
  `Last-Event-ID`，重放缓冲仅补给有断口的连接。
- **结果**：**前后对比验证**——同一场景（5 MB 工具输出 + 一个永不读取的 SSE 客户端），旧实现 45 秒内回合
  始终无法结束，新实现正常跑完（steps=2）；`Web*Test`（拆分前的 `WebApiTest`）的用例覆盖路由、token 门、Host 白名单、
  审批握手、工作区切换与会话删除。
- 前端另有**手写的流式 Markdown 渲染器**（零依赖、零构建）：每次 flush 重解析整段源码，但**源码没变的块
  复用已有节点**，所以答案多写一个词只重建它正在写的那一块——滚动位置、选区、正在读的段落都不被打断；
  安全上**从不解释原始 HTML**（全文无 `innerHTML`）、过滤链接 scheme、不抓取图片。用例拆在
  `src/test/js/markdown.test.mjs`（44 条断言，把渲染器源码抽出来跑在迷你 DOM 上，`mvn test` 会自动跑）。

### 4. 端到端测试：把「真实边界」放进 CI
- **做法**：`MockModelServer` 用 chunked 传输并**故意把 SSE 帧切碎**；`CliEndToEndTest` 走真实 CLI →
  HTTP → SSE → 工具 → 文件系统 → 会话文件，两种协议各跑一遍，含拒绝审批路径与退出码；`FakeServer`
  为 Provider 单测提供脚本化的分片响应。
- **结果**：884 个测试离线全绿，两分钟内跑完；「只有真实进程才会暴露」的分帧、进程超时、管道关闭等问题
  都有回归测试。

### 5. 安全默认值（本地工具，但仍然按不可信输入设计）
| 面 | 做法 |
|---|---|
| 写操作 | `write`/`edit`/`bash` 一律先审批；无 TTY 时**默认拒绝**并说明如何显式允许（`--yolo`） |
| Web 暴露 | 非 loopback 绑定**强制** token；URL 携带 token → HttpOnly cookie，前端零 token 逻辑 |
| DNS rebinding | 无 token 时要求 loopback `Host`；**绝不解析域名**做判断（只接受 `localhost` 与回环字面量） |
| 请求体 | 1 MiB 上限，超出返回 413，而不是 `readAllBytes()` 把堆吃光 |
| 路径穿越 | 会话 id 走 `[A-Za-z0-9][A-Za-z0-9._-]*` 白名单，`../` 到不了文件系统 |
| 密钥 | 只回传「有没有 / 来自哪」，永远不回传密钥本身；自定义 Provider 用**自己的**环境变量名取 key（避免把 OpenAI 的 key 发给第三方中继） |

### 6. 一致性与可恢复性
- 会话是 append-only JSONL，**每行一次 `write` 调用**（避免刷新侧边栏时读到半行 JSON），每条消息即时 flush，
  因此被 kill 掉也只剩最后一条未落盘；用量是同一文件里的 `usage` 记录，重开会话继续累计。
- 空会话不落文件（id 免费，文件是一次声明）；删除会话只删文件，不删工作区目录。
- **重启会回到你原来那个对话**：restart 会换掉进程，而新进程默认开新会话——于是「你要它更新的那一刻」恰好丢掉
  你正在看的东西。所以退出前把当前会话 id 写进 `<home>/resume`，下一个进程读它并打开；读完即清（只对这一次重启
  生效，之后照常开新会话），显式的 `--resume` / `--continue` 优先级更高。真实跑过：`--repl` 重启前后打印同一个
  session id，Web 模式重启后 `/api/status` 报同一会话且 738 条历史都在。
- **取消是真实的**：`abort` 通过 `ToolContext.isCancelled()` 传进工具，`bash` 每 150ms 轮询，
  正在跑的进程树会被杀掉并回一条「aborted by the user」的结果——而不是让用户等十分钟超时。
- **中断不会毁掉会话，错位也不会**：assistant 的 tool_calls 先落盘、结果后落盘，中途中断就会留下「有调用
  没结果」的非法历史，两种协议都会永久拒收这条会话（报错还完全看不出原因）。`SessionRepair` 在**请求
  投影**上补齐「not run」结果（append-only 的文件不重写），并在对话里说明补了什么；如果有一条消息挤进了
  某一轮的答案中间（同一会话第二个写者、探针直接 append 到文件），真实结果就不再紧跟它的 assistant，
  OpenAI 同样 400（`Messages with role 'tool' must be a response to a preceding message with
  'tool_calls'`），所以修复器按**调用**归位而不是只看相邻：真正的结果被带回它所属的那一轮，实在没有
  归属的结果（调用根本没记录、或同一条重复出现）则不进请求并在 notice 里点名——一条 API 放不下的 tool
  消息和不存在的调用一样，都是被拒的请求。这条是用户报来的真实故障：旧 jar 复现出「投影仍有 1 处非法」，
  修复后同一份 784 条消息的真实会话投影零问题，另用真实 OpenAI 请求体形状校验了 9 个会话文件。
- **审批不会因为你「看别处」而消失**：审批是**内存里阻塞的请求**、不是消息，所以重放对话永远带不回它——
  切走再切回时，如果只靠 history，问题框就没了，只剩 abort（用户实测报回来的 bug）。修法是把待批请求放进该
  会话的 `status`（`Pending` 记住 title/detail，不只记住那个 future），前端用同一个 `renderApproval` 重画；
  重放进行中收到的请求先挂起（`pendingApprovalsSync`），否则刚画好就被重建的 transcript 冲掉——那正是它要解决的
  丢失；服务器已不再持有的请求标记为「No longer waiting」而不是留一个永远点不动的框。每个会话只看到自己的待批，
  所以在一个会话上点批准不会替另一个会话作答。
- **只在安全的地方并发**：工具用 `readOnly()` 自述，只有连续只读调用会并发（一调用一虚拟线程，
  结果按模型请求顺序写回会话）；写/执行类调用始终串行，因为「两次写、顺序未知」不叫记录。

### 7. 上下文预算（旗舰特性）
- 会话落盘无限增长而模型窗口有限，因此每次请求都是对话的**投影**：先抹旧工具输出（内容换成标记，
  call/result 配对保留，wire 仍合法），再按「整轮」从最旧一端丢弃，最后才截断当前轮次里最大的那个结果并显式标注。
- 三个阶段各自都有理由：工具输出是上下文里体积最大、价值最低的部分；半条调用会直接被 API 拒绝而不是变小；
  当前轮次是模型正在推理的数据，动它才是本末倒置。
- 估算器（`TokenEstimate`）明确声明是启发式：ASCII≈4 字符/token，CJK/emoji≈1 字符/token；不追求精确，
  只要求不把量级估错三倍——否则预算比没有预算更糟。
- 侧栏显示「本会话占多少 / 预算多少」，超预算变红；**刻意不显示金额**：算钱要依赖一张别人随时会改的价目表，
  一个看着合理的错数字比一个空缺更糟——这条取舍本身也是设计决定。

## 四、架构（依赖单向，`core` 不认识任何具体实现）

```
  cli/     CliOptions → Config → Cli ──┬─ one-shot / REPL / --web
                                        │
  core/    AgentLoop ── Provider（接口） ── provider/（HTTP + SSE，双协议）
             │           ToolRegistry ──── tool/（文件系统、shell、只读标记、取消信号）
             │           ContextBudget ─── TokenEstimate（请求投影 + 估算器）
             │           SessionRepair ─── 中断留下的「有调用没结果」在投影上补齐
             │           Session ──────── session/（磁盘 JSONL）
             │           AgentListener ── ui/（终端渲染）、web/（AgentHub「每会话一个 Conversation」+ HttpApi + 页面）
             └─ Config / AppPaths / Message / Json
```

关键取舍：`core` 只依赖接口 → 同一个 `AgentLoop` 在单测里跑脚本化 Provider、在端到端里跑 Mock HTTP 服务、
在生产里跑真实中继；新增工具/协议/前端都只需实现一个接口。会话文件是完整记录，请求是它的投影——
「留下什么」和「发出去什么」是两个决定，各自都能单独测试。

## 五、工程决策与代价（面试常问「为什么」）

| 决策 | 理由 | 代价 / 取舍 |
|---|---|---|
| 不引入 Web 框架 / SSE 库 | 本地工具，一个 jar 启动即可，依赖越少越可信 | 自己处理分帧、心跳、背压、断线重连 |
| tool 参数保持字符串 | 核心层不解析厂商负载；畸形参数→错误结果而非崩溃 | 各端各自解析一次 |
| Anthropic 的 tool_result 合并进同一条 user 回合 | 协议要求；否则 400 | 会话模型与 wire 模型之间多一层转换 |
| 统计里区分「未上报」与「0」 | 缓存命中率 0% 与「没有信息」是两件事 | 前后端都要用 `null` 而不是 0 表示未知 |
| 每个会话一次只跑一个回合 | 两个写者写同一份会话 = 转录损坏；但**不同会话可以同时跑**（会话级运行态 + 事件带 sessionId） | 同一工作目录里的并发写没有排序保证（等同于开两个终端）；改所有会话地基的操作（换模型/切工作区）仍需全局空闲 |
| 不设步数上限 | 上限分不清「模型卡住」和「任务很长」，砍错就是让一次本会成功的运行失败 | 卡死的模型会一直调工具，得有人看着并 abort |
| 审批默认拒绝 | 管道/CI 里不能「不小心」批准 `rm -rf` | 无 TTY 时必须显式 `--yolo` |

## 六、可以主动展开的细节（面试问答素材）

1. **「流式 tool_call 怎么组装？」** 按 `index` 建表、首片带 `id`/`name`、后续只追加 `arguments`；网关省略
   `index` 时用「带 id 视为新调用、纯参数视为续写」兜底，否则两个并行调用会被拼成一个损坏的调用。
2. **「SSE 你自己写的，边界怎么处理？」** `BodyHandlers.ofLines()` 负责 UTF-8 不跨行的还原，我负责帧语义：
   多行 `data:` 用 `\n` 连接、`:` 开头是注释、空行才派发、`[DONE]` 结束、流末尾的悬挂帧照常返回。
3. **「重试策略？」** 只重试连接阶段的 `IOException` / 408 / 429 / 5xx，指数退避 + 抖动，最多 3 次；
   4xx 立即失败（请求本身错了，重试只是烧钱）；**流中途失败不重放**（增量已渲染，重放会重复）。
4. **「一次回合怎么被叫停？」** `AgentLoop.abort()` 置原子标志，循环在「步骤之间」和「每个工具调用之前」
   检查；工具内部的停止交给各自的超时（`bash` 120s 默认、最多 600s，超时杀整棵进程树）。**刻意不设步数
   上限**——上限分不清「模型卡住」和「任务很长」，砍错的代价是让一次本会成功的运行失败，所以停不停交给人。
   代价是中断点可能正好落在「assistant 已落盘、工具结果未落盘」的窗口里，于是有 `SessionRepair`：在**请求
   投影**上补齐「not run」结果，会话文件不重写，坏历史也不会让之后每个请求都被永久拒绝。同一条修复还按
   **调用**（而不是相邻关系）归位结果：答案被别的消息挤开时带回原轮，没有归属的结果不进请求——否则报的是
   另一个方向但同样致命的 400（`Messages with role 'tool' must be a response to a preceding message with
   'tool_calls'`）。
5. **「工具输出太大怎么办？」** 统一 `outputLimitBytes`：`bash` 保留头 60% + 尾 40% 并报告省略字节数；
   `read` 按行窗口分页，**超出预算的单行会被截断而不是跳过**（否则模型永远卡在同一页）。
6. **「编辑工具怎么做安全替换？」** 精确字符串匹配（非正则）、唯一性检查 + 有提示的失败（「折叠空白后有
   N 处匹配」）、`replace_all` 显式开关、替换前用 LCS/precise-or-coarse 双模式生成有界 diff 供审批预览。
7. **「用量统计怎么算？」** 两协议语义不同：OpenAI 的 `cached_tokens` 已含在 `prompt_tokens` 内；Anthropic 的
   `cache_read/creation` 是**附加**的，所以 prompt 大小取三者之和。显式 `null` 一律视为「未上报」。
8. **「虚拟线程用在哪？」** 三处：`bash` 的输出泵（一个纯阻塞的读循环）、同一回合里连续的只读工具调用
   （一调用一虚拟线程，结果按模型请求顺序落盘）、以及 Web 层每个 HTTP/SSE 连接一个虚拟线程。唯一刻意的
   例外是：一个 SSE 连接需要一个**受控**线程来独占写它的 socket 并做心跳，那里要的是独立线程而不是调度器。
9. **「怎么保证不改坏？」** 每个修复先写复现用例（红）→ 修 → 绿，并把复现留在正式测试类里；
   行为变更同时更新 README/docs，避免文档与代码互相打脸。
10. **「长对话怎么办？」** 上下文预算是三阶段的投影：抹旧工具输出 → 丢最旧整轮 → 截断当前最大结果；
    有属性测试遍历多个预算，断言任何投影都不出现「有调用没结果」——这正是两种 wire 格式都会校验的形状。
11. **「abort 真的能停下正在跑的命令吗？」** 能。abort 标志经 `ToolContext` 传进工具，`bash` 在等待进程时每 150ms
    看一眼，命中就杀进程树并回一条错误结果；测试用 `sleep 30` + 中途 abort 断言 3 秒内返回。
12. **「为什么只有只读工具并发？」** 因为并发只对「不改变任何东西」的调用安全；写和执行类调用保持串行，
    结果顺序就是模型请求的顺序。并发部分的渲染回调在循环里串行化——渲染器是有状态的，给它两个线程是等着出 bug。
12b. **「怎么让一个对话跑着时还能开另一个对话？」** 把「运行态」从实例级下放到**会话级**：`AgentHub` 每个会话
    持一个 `Conversation`（回合标志、正在跑的 `AgentLoop`、这个会话自己的用量账本），每个回合一条虚拟线程；
    事件带 `sessionId`，前端只渲染当前会话、把别的会话只当「运行中的行」来标记；拒绝的粒度从「全局」精确到
    「它碰到的东西」——切/删一个会话只需那个会话空闲，改 provider / config / 工作区仍需全部空闲（那是所有会话
    脚下的地基）。`AgentLoop` 一行没改：它本来就只管一个会话，并发住在「拥有会话的那一层」。abort 也是按会话的，
    并且会顺带拒掉该会话待批的审批——否则后台会话卡在审批上根本停不下来。
    真实数据验证：b 跑 6 秒慢任务期间 a 提交并被接受、a 的 `status.busy=false` 而 `running=[b]`、b 再发一条仍被
    409 拒、侧栏 b 行标 running、从 a 用 `POST /api/abort?id=b` 能停掉 b。
    
    **踩过的坑（用户实测报回来的）**：第一版把「拒绝的粒度」定错了，导致 a 在跑时**点不进 a**（切换被 409 拒，
    而切换恰恰是用户唯一想做的事），也进不了别的工作区的对话。修正后的规则是：**「看」任何会话都不被拒**
    （包括正在跑的那个——把它的 `FileSession` 原样交回去，而不是开第二个写者）；每个 `Conversation` 在自己回合
    启动那一刻**锁定 cwd**，所以切工作区不会把跑到一半的任务改到别的目录，加工作区/切工作区也就无需全局空闲；
    真正必须等的只剩「删掉它正在写的文件」和「换掉它脚下的模型」。这条用真实进程验过：提交后立刻切到 ws2，a 的
    `pwd > where-am-i.txt` 仍写在 ws1（ws2 里没有该文件）。
13. **「浏览器控制台踩过什么坑？」** 两个都是真的：①发布线程直接写 socket 会被一个不读的客户端拖死，
    改成每连接有界队列 + 由连接线程独占写；②页面在 POST 返回后才置「忙碌」，而毫秒级回合早在事件流上结束了，
    于是界面永久卡在「运行中」并静默吞掉下一条消息——改成乐观置位、以事件流为准，并加了「回到前台重新对表」的自愈。
14. **「还能怎么扩展？」** 工具/协议/前端都是接口；`ModelCatalog` 已是为「路由器式目录」预留的缝，
    未来可接网络目录并加缓存；`AgentListener` 可以换成任意前端。

## 八、2026-10 这一批：五件围绕循环的东西（每条都带着量出来的数字）

这一批的选法只有一个标准：**面试官会追问的那几个问题**——你怎么知道改了提示词没变坏？线上慢了你怎么定位？
你说你会 RAG，召回多少？协议你懂几层？——都得有一个能跑的东西接住。

### 1. 指标与痕迹（`obs/`：手写 Prometheus + 回合级 span 树）

- 每个数字都从 `AgentListener` 来：`AgentLoop` 只多了两个回调（`onRunStart` / `onRunEnd(result, failure)`），
  **一行记账都没有进循环**。观察者是包在真正前端外面的一层装饰，前端拿到的回调一字不差——有一条用例专门钉住
  这件事：漏一次 `onText`，指标上完全看不出来，而页面上会少一段回答。
- `GET /metrics`：手写的 Prometheus 文本格式（`text/plain; version=0.0.4`），16 个指标——运行按结局、模型回合数
  与它的时延直方图、工具调用与错误（按工具）、工具耗时直方图、token 按方向、审批的答案与**等待时长**、SSE
  连接数与因跟不上被丢弃的客户端数、排队消息数、每回合固定前缀的估算 token、列一次会话的耗时。
- `GET /api/trace`：屏幕上那个会话**最近一次运行**的 span 树。工具挂在**提出它们的那个回合**下面——一次循环
  的迭代是「问模型一次，再跑它要求的工具」，把工具摆成回合的兄弟节点，「这一次为什么慢」在树里就读不出来。
- 审批的等待时长由一层独立的装饰（`MeteredApprover`）记：审批发生在一次工具调用的**里面**，不经过循环的回调
  ——这是这一层唯一必须自己包住的东西。
- 三个刻意做对的细节：标签在**登记时**校验（写错一个字母，那个数字会安静地消失，而没有任何东西会失败）；
  负的观测在调用点被拒（循环用 `-1` 表示「从未运行」，当成一次 0 毫秒的观测记进去，直方图里就多出一次从未
  发生的事）；没有观测的直方图什么都不输出（`name 0` 会让抓取端读到一个没有 `_count` 的「直方图」）。
- `--trace <file>` 把每棵 span 树追加进一份 JSONL，默认关着（一份没人要的痕迹会安静地长在磁盘上）。

### 2. 离线评测门（`eval/` + `evals/`）

- 一行一个 JSON 任务：`prompt`、初始 `files`、模型那一侧的 `script`（每一步 `tool`/`tools`/`text`/`usage`），
  以及 `expect`（文件内容、不该存在的路径、回答里必须出现的片段、**工具调用序列**、步数上限）。
- 每个任务跑在一个**临时目录**里，跑完就删：它看不见这个仓库，也看不见上一个任务的残留。
- `ccj --eval <file|dir>` 打印一张带步数、工具调用、token、耗时的表，**按「全部通过」决定退出码**；
  `EvalSuiteTest` 让发布出去的那 9 个任务成为 `./mvnw test` 的一部分——只在人看着的时候跑的套件，和有断言的门
  是两件事。
- 发布的那一套**全部离线**（不允许有需要模型的任务）：一道有时绿、有时红的门不是门，是一次抽奖。
- 报告里的 token 不是从别处读来的：由 `Recorder` 记，与 web 面板上的那些是同一个计数器的两次读取。
- 任务是代码，所以路径不能跑出它的工作目录（`../` 被拒绝）；运行抛异常的是一条**失败**，不是一场崩溃。

### 3. MCP 双向（`--mcp-serve`）

- 既然这个代理能调用别人的工具，反过来读就是同一句话——而这句话的完整实现只有 300 行出头。
- 三条规矩与客户端对称：**同一个 `approvals.json`**（这个进程的 stdin 是协议通道，没有终端可问；没有规则的
  调用默认被拒，放行只有 `--yolo` 或用户自己写下的一条规则两条路）；**工具自己的话就是结果**（未知工具名是
  工具错误而不是协议错误，因为调用方的模型有权读到它）；**stdout 只属于协议**（连「规则自动放行」的那句回答
  都走 stderr——一个字节写错地方，就是一条解析不了的响应）。
- `restart` 不在这张表里：它能把这个进程连同会话一起结束，而远端的调用者只会看到连接断掉。
- 最值钱的一条用例让两半面对面：**真的 `McpClient` 开着真的 `ccj --mcp-serve` 子进程**（真 stdin/stdout、
  真握手），读一个文件、被拒绝一次写入、再被一条规则放行一次。一个只对着手写字符串测过的协议实现，测的是它
  自己以为的形状。
- 顺带一件值得讲的事：这个文件第一次跑 `./mvnw verify` 是**红的**——仓库自己的拼写约定测试指出 `initialize`
  这个名字按本仓库的规矩是美式拼法。改成 `handshake()`，那颗协议的词只留在 `case` 标签里。**一个仓库能抓住
  它自己的作者**，这是「规则被机器守着」的现场证据。

### 4. 语义检索（`recall`，以及它的出口审批）

- 只在有 `embeddings.json` 时才进工具表（与 MCP 服务器同一条规矩）：没配置的机器上，模型看不到一个它用不了
  的工具。只讲 OpenAI 形状的 `POST /embeddings`（这一行事实上通用的那一种），所以「用本机的一个小模型算向量」
  不需要任何新适配器。
- **它是这个代理里唯一一个把工作目录里的文字送出去的东西**，所以它是唯一一个审批提示里带着数字的工具
  （「把 N 个块的文字发给 …」）；而一次没有改动的检索**谁都不问**——块的内容没变、指纹没变、向量已经在索引
  里，没有出口，也就没有问题。
- 指纹算的是**内容加位置**：改一个文件只重算它改动了的那几块（实测：三份文件的语料改其中一份，只有它自己那
  一块被重算）；换模型就是整份重建（两个模型的向量不在同一个空间里，那里的点积**不会报错**，只会给出没有意义的
  相似度）。
- 检索质量量过：20 份各讲一件事的文件 + 10 句只与其中一份共享词的问题（整句原样不出现在任何文件里，所以这是
  检索不是 grep）→ **recall@1=0.90、recall@5=1.00、MRR=0.95**。近似索引（HNSW 那一类）没做，理由有数字撑着：
  几千个块上暴力搜索是毫秒级，近似换来的是七十微秒与一次「可能漏掉真正最近的那个」。
- **诚实的那一半**：仓库里没有一个数字来自真实的嵌入模型，本机只跑通了替身端点——「换个真模型召回多少」是一句
  没有被验证过的话。

### 5. 开销账本（`docs/PERF.md`）

- 三笔会被感觉到的开销，量出来并写下方法：启动到打印版本 **54 ms**、到工具表建好可以收下第一条消息 **574 ms**、
  每个回合固定重发的前缀 **1908 token**（系统 245 + 8 个工具的 schema 1663）、列一个 2 MiB / 2715 条的会话
  **21 ms**（缓存命中 0 ms）。
- `ccj --tools` 现在把每个工具的估算 token 与合计一起打印——于是「再加一个 MCP 服务器或 `recall` 值多少 token」
  有一个当场可读的答案（实测 `recall` = +187）。
- **一处计划中的优化被量掉并否掉了**：把「列会话时整个解码」改成「只解标题那一行、其余只数行数」，四兆字节的
  会话从十五毫秒变五毫秒——省十毫秒，代价是丢掉「损坏的会话在列表里就以损坏的样子出现」这条性质。**一个能说清
  自己否掉了什么、以及为什么的人，比一个什么都说做了的人可信。**

### 这一批给面试问答加的五条

1. **「你怎么知道改了提示词 / 换了模型没变差？」** 跑 `evals/`：离线、可重复、带步数与 token 的回归门，全过退出 0。
2. **「线上慢了你怎么定位？」** `/metrics` 说「现在怎么样」（工具耗时直方图、模型回合时延、审批等待、SSE 丢弃），
   `/api/trace` 说「那一次到底发生了什么」（`run → turn(0) → tool(read)` 那棵树）。
3. **「RAG 你做到哪一步？」** 切块与重叠、内容指纹的增量索引、归一化向量与暴力前 k、**量到的 recall@1/@5/MRR**，
   以及「近似索引在这个规模上买不到东西」这句有数字撑着的话。
4. **「协议你懂到哪一层？」** 同一个 MCP 协议的两半都在这个仓库里：客户端（stdio、按 id 应答、通知不当作答案、
   stderr 排空、每请求截止时间）与服务器（能力申明、工具表、工具错误与协议错误的区分），而它们被一条「真客户端
   开着真服务器」的用例钉在一起。
5. **「为什么没有 Spring / MySQL / Redis？」** 因为这是一个本地工具，而可读性是它最大的资产（26k 行、一个运行时
   依赖、一个下午读完）。要在这一层演示那些技术，正确的做法是另开一个模块把 `AgentLoop` 当库嵌进去——它只依赖
   接口：会话是接口、工具是接口、提供方是接口，所以换成 JDBC 或 Redis 不需要动循环一行。

### 6. 收据：让工具自己承认它不知道什么（同一天的第二个批次）

- 一个回合结束时（终端 `/receipt`、网页上的按钮、`GET /api/receipt`）：改了什么文件、跑了哪些命令与退出码、
  这一轮花了多少 token，以及**哪些事没有验证**——改过却没有被任何检查碰过的文件、被拒绝的调用、从未运行的
  调用、贴着输出上限的结果、这一轮的压缩。
- **它从已经存在的东西推导，不新记一份账**：文件清单来自检查点（与 `GET /api/undo` 的预览是**同一段代码**，
  所以两者不可能对不上——而验收就是一条把两边逐字比对的用例）、命令与退出码来自转录里「调用↔结果」按 id 的
  配对、token 是账本前后两次快照之差。推导逻辑一份，两个前端共用。
- 两处刻意的「不」：退出码读不出来就是 `null`（`exit code -1 (超时)` 不是退出码，收据不编一个 0）；**不检测
  输出被截断**——各工具的省略提示是给人看的一句话，按句子做模式匹配会猜，所以它报告「贴着上限」这个确定的事实
  并说明为什么。**一个会猜的收据，比一个说「这一条我读不出来」的收据更糟。**
- 网页上那一次点击是**真的点过**的：headless Chrome 经 CDP（`browser-smoke.mjs`）多走一步——点 `#btn-receipt`，
  等面板里出现含「收据 · 会话」与「没有验证」的正文。

### 7. 导出：一份能拿走的会话

- `ccj --export <id>`（stdout）+ 网页上的 `<a download>`（`GET /api/export?id=`）：一份**自包含** HTML——样式
  内联、图片以 `data:` URL 内联成缩略图、没有一行脚本——断网也打得开。
- 三条规矩各有一条用例：自包含（页面里没有任何 `http://` 与 `<script`）、**可重复**（导出时间是唯一的外部
  输入；同一会话同一时刻导出两次字节完全相同，HTTP 那条比的是「去掉时间戳之后逐字节相同」）、**不改动原文件**
  （对会话文件与附件目录做（路径、大小、修改时间）快照比对）。
- 模型正文一律转义后进 `<pre>`：用例里专门放 `<script>alert(1)</script>` 进去，因为一份生成的 HTML 最容易
  在插值处少一个转义。
- 顺手一次该做的重构：`Thumbnails` 从 `web/` 搬到 `session/`（附件是会话的，缩略图是附件的派生物），附件名的
  解析收成一处 `AttachmentStore.resolve`，导出与缩略图端点从此走同一个「必须在目录里、必须是平面文件名」的判断。

**这两项给面试加的两条**：
- **「你这个工具会不会报喜不报忧？」** 会——收据里那一节叫「没有验证」，它列出改过却没被检查碰过的文件、被拒
  绝的调用、贴着输出上限的结果，并明说哪些它读不出来。**能说清自己不知道什么的人，比什么都说做了的人可信。**
- **「导出这种小事有什么难的？」** 自包含（断网可开）、可重复（能被 diff）、只读（快照比对钉住）、纯文本渲染
  （转义）——四件小事各有一条用例，而每一件的失败方式都是安静的。
