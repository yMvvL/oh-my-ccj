# 路线图

这个项目要往哪走，按照工作真正必须发生的顺序。

有两条规则决定这个顺序。**无法核验的主张是负债**，所以验证排在功能之前——包括纸面上已经存在的功能。而**护栏就是产品本身**：这是一个以你的身份运行命令的工具，因此任何在未经询问的前提下扩大它能做的事情的改动，都比任何让它更快的改动更重大。

下面用到的状态标记：`todo`、`doing`、`done`、`blocked`。

## Phase 0 —— 让主张可核验 —— `done`，尾巴也收完了

**落地了什么，以及它换来了什么。** Maven Wrapper 固定 Maven 版本，所以贡献者跑的构建就是 CI 跑的那份。一个 GitHub Actions 工作流在两个平台上运行测试套件、打包 jar 并启动它——这是唯一能把「542 个测试通过」从主张变成证据的东西。而 Node 用例文件现在在跑不起来时会报告为 *skipped* 而不是通过，并且有一个测试通过 `TestAbortedException` 钉住这个行为。

这份清单曾经有三处尾巴，现在一处都不剩：

- **测试数量不再写进 README 与工作流**（第一处，早先关掉）：这个数字每加一个测试就会漂移，而徽章才是活的答案。
- **编译器插件的版本写下来了**（`maven-compiler-plugin` 3.15.0——就是本 wrapper（Maven 3.9.16）自己会绑定的那一个；写下来是为了让读者能核对，不是为了换一个版本）。
- **「文件在、断言没跑」这一整个家族都关掉了**：两个用例（`theAnswerIsRenderedAsMarkdown`、`theRendererBuildsNodesAndNeverHtmlSource`）曾在 `app.js` 缺失时提前返回，而 JUnit 把它们记成通过。修法不是改那两处，而是把**六份**各写一遍的 `appSource()` 收成一个 `WebSessionRowTest.appSourceOrSkip()`：读不到就抛 `TestAbortedException`——和这个包已经为「缺少 node」钉下的规矩同一条。同一次收敛里，两处用 `assertTrue(script != null, "app.js 必须可读")` 的断言也换掉了：那是个失败，但它报的是「文件不在」，而不是「用例没跑」。

## Phase 1 —— 补上仍然敞着的正确性缺口

**为什么排在新能力之前。** 这里每一项都是「常见路径上代码是对的、边缘处是错的」的情况，而边缘正是编码代理被用起来的地方：长会话、好几个对话、用户在自己的编辑器里编辑同一个文件。

**最近关闭的**，列在这里是为了让下面的清单不会被当成一份永不挪动的积压：子代理暂存逃逸及随之而来的共享目录清理（两者都随该目录一起移除）、无法审批的子代理写入、`edit` 和 `write` 拒绝一个在审批等待期间被改动或出现的文件、两次写入改成先暂存再重命名而不是原地写、跨源状态更改、错误响应体在被截断前读到末尾，以及一个把缺失运行时报成通过的 Node 用例文件。全部靠读源码验证——没有一项是在写这份清单的这台机器上跑出来的。

- **1.1 两个对话，一个文件** —— `done`。`write` 在提示显示之前给文件取指纹——大小、修改时间，以及逐字节流式计算出的哈希——并在答案回来时指纹不再匹配就拒绝，方式和它此前已经拒绝一个在审批期间*出现*的文件一样。只有大小和时间戳是不够的：编辑器以同样的粒度保存，或者格式化工具回写同样多的字节，都会溜过去。README 里那处暴露面仍在原地，也是站得住的——`bash` 在对话之间没有顺序——而且它不再覆盖一个先显示差异、然后写入别的东西的工具。
  *验收已满足：* 覆盖写入的那种情况被检测并拒绝，拒绝消息说明了要重做什么。
- **1.2 在运行中途触发的截止时间** —— `done`。机制本来就在（`SubAgentRunner.Deadline` 是一条 daemon 线
  程，到点置位并 `loop.abort()`），缺的是**证据**：触发那半边此前只在它产生的那条消息层面有断言——把一句手
  写字符串喂给 `SubAgentReport.failed`，从未真的让截止时间到期，也没经过 `SubAgentRunner`、`AgentLoop`、
  `Deadline` 任何一环。现在 `aSubAgentThatNeverStopsIsCutOffAtItsDeadline` 用一个「正常时永不返回、被中断
  时立刻退出」的提供方（`while (true) Thread.sleep(25)`）把整条链路跑通：700 毫秒的截止时间切断了它，报告
  是 failed 且说出理由，写锁被放开。顺路修掉一处自欺：报告用 `Duration.toMinutes()` 说上限，于是 90 秒会
  被说成「1 分钟」、45 秒会被说成「0 分钟」——一句「跑过了它的 0 分钟截止时间」会让读的人以为护栏坏了。
  *验收已满足：* 一个永不停止的脚本化子代理在截止时间被切断，且它的报告说明了这一点。
- **1.3 用量记账** —— `done`，而这条等号在做的过程中抓到两个真问题。**第一**：终端一个 token 都不记
  ——账本只在网页那条路上被写，于是 `--max-total-tokens` 在 REPL 与 `-p` 里永远不触发，一条终端会话的文件
  里除了压缩次数什么都没有。账本现在由**循环本身**记（它是唯一知道会话的那个东西，也是两个前端都有的那个
  东西），网页端不再记第二遍。**第二**：压缩那一次摘要请求的用量被整个丢掉（监听器是 `event -> {}`，
  只有 `compactions` 那一格留下痕迹），而用户为它付钱——每次压缩都让花费上限少算一笔。现在它进账本，但不
  占 `steps`/`turns`。顺带修掉两处口径：OpenAI 那个提供方此前对**每个 chunk** 都转发一次 usage（某些网关
  每帧重复发累计用量，同一笔钱会按 chunk 数被记上几十遍），现在一个回合只在流结束时交一次；子代理没上报
  缓存时，命中率不再从「未上报」变成 0.0%。
  *验收已满足：* `theLedgerEqualsWhatTheProvidersReportedAcrossADelegationAndACompaction`——八组往来、
  一回合委派（主代理两次 + 子代理一次）、一次压缩，每次都报一笔不同的账：面板的 11828/1208/2988 与脚本逐
  回合之和逐位相等（三笔账互不相同，所以任何一种少算都落在不同的差值上，不会凑成一个看起来对的数字）。
  终端那半边由 `aTerminalTurnRecordsWhatTheProviderReportedAndTheCapReadsIt` 钉住：文件里出现提供方报的
  数字，而紧接着的回合因为超过上限被拒、模型没有被问第二次。
- **1.4 会话文件无限增长** —— `done`，决定是**不裁剪**，而理由带着测量：本机上最大的会话是 2.4 MB /
  3982 行，全部会话加起来 11.5 MB，而其中相当一部分是账本行（网页模式下每个回合约 2S+2T+3 条、每条约 190
  字节）。一个长会话的文件**就是它的记录**，而上下文另有一条路管着（`ContextBudget` 投影每次请求、
  `/compact` 另起一代且原件不动）。所以：不自动裁剪、不自动删除，也不给一个会让人以为「文件不会大」的
  上限。真正该修的不是文件，是**读它的人**（侧栏每次列会话都会把变更过的会话整个解码、正在写的那条每回合
  整份重解析），那件事连同启动与每回合前缀的开销一起进了 **4.5**，因为它需要先量出数字。
  *验收已满足：* 一份写下来的决定（本节），而「裁剪」那条分支被明确否掉，理由与被否掉的代价都在这里。
- **1.5 一个驱动页面的测试** —— `done`。`src/test/js/browser-smoke.mjs`（零依赖、零 npm）自己用 CDP 说
  话：找一个能用的 Chrome（`CCJ_CHROME` 优先）、以 headless 起来、从 stderr 的 `DevTools listening on`
  取端点、用 node 自带的全局 `WebSocket` 建立连接，然后驱动**发布出去的那个页面**——等输入框与工具列表出现、
  真的用 `Input.insertText` 敲进一句话、真的按一下发送按钮、再等助手的回答出现在 DOM 里。Java 那边的
  `WebBrowserSmokeTest` 起真服务器（demo 提供方，端口 0）并断言回答里有**磁盘上的哨兵**：那串东西页面
  编不出来，所以它出现就等于「浏览器 → HTTP/SSE → 循环 → 工具真的读了文件 → 回答回到 DOM」整条路走通了。
  三种结局都有实测：跑通退 0；没有能用的浏览器、或 node 没有全局 WebSocket（要 22.4+）退 3 → JUnit 记成
  **skipped**；失败退 1 并把页面证据（状态行、输入框里的字、转录里几段回答）打出来。CI 的 node 因此从 20
  升到 22：按 20 装的话它在两个平台上都会变成 skipped，而「可选」退化成「从没跑过」就不是可选了。
  *验收已满足：* 本机真的跑通（1.2 秒，`/usr/bin/google-chrome-stable`），并且在真的把浏览器或运行时拿掉
  之后分别看到 skipped 与 failed。

## Phase 2 —— 能力，按它挣得自己位置的顺序

**为什么是这个顺序。** 每一项都按照「在不削弱审批叙事的前提下，它能扩大代理能做的事多少」来评判。任何需要沙箱才安全的东西现在都不属于这里。

- **2.0 图片** —— `done`，而形状在真机上被改过一次。上传让一个独立的视觉模型描述这张图片，而描述**等着**
  和用户的下一句话一起发出去——不是自己开启一个回合（见 [VISION.md](VISION.md) 里「用起来之后的修正」）。
  进入对话的是描述，不是图像，而文件存放在会话旁边而不是项目里。按钮先问**相机**还是**相册**。
  *验收，已满足：* 用一张真实 PNG `POST /api/attachment` 会让描述出现在响应、`status` 和 `picture` 事件里，
  而**转录里什么都没有**（没有 `user` 事件、没有模型请求）；随后一条消息把描述和用户的要求拼成一条并开启
  回合，图片在磁盘上的 `<id>.attachments/` 下，而每一种拒绝（不是图片、超过 8 MB、没有视觉模型、点名一张
  并不持有的图片）都让视觉端点没被调用、或者什么都没发出去。设计、测量结果以及未验证的部分见
  [VISION.md](VISION.md)。
- **2.1 一个 MCP 客户端** —— `done`，作为 2.5.6。远程工具经由同一个 `ToolRegistry` 和同一个审批者进入，服务器的工具以该服务器的名义命名——`mcp__fs__read_file`——在提示、转录和规则里都是如此。见 [MCP.md](MCP.md)。
  *验收已满足：* 一个已配置服务器的工具走审批路径跑了起来，并被一条规则答复；一次拒绝把它挡了下来。
- **2.2 更多协议** —— `done`。四种线路：`openai`（`/chat/completions`）、`anthropic`（messages
  API）、**`openai-responses`**（Responses API）与 **`gemini`**（`:streamGenerateContent`）。两条路都能选
  中它们——直接用协议名当 `--provider`，或作为一个自定义定义的 `kind`（名字归用户，协议归代码：同一个实现
  类，因为「哪家厂商」和「哪种线路」是两件事）。Responses 那条按核过的形状写：平铺的工具定义、助手历史作为
  输出项回填、工具结果用 `function_call_output` + `call_id`、usage 只在 `response.completed` 里、
  **显式 `store:false`**（它的默认值是 true，而这里的叙事是会话在我的文件里）。Gemini 那边记下了两条差异
  的关键：`FunctionCall.args` 是 JSON 对象而不是字符串（双向转换写了退路），以及 `?alt=sse` 这个分帧方式
  **未核实**——proto 里没有它。
  *验收已满足：* 同一个 `FakeServer` 桩（按 19 字节切块，帧内 JSON 也在 token 中间断开）对每种映射都有用例：
  请求体逐字段相等、事件序列、工具参数分片拼装、带缓存的 usage、未知事件忽略、错误 payload 抛出。Responses
  12 例、Gemini 13 例，另加 `ProvidersTest` 里两条「按名字能否选中、请求打到哪个路径」的接线用例。三个提供方
  的既有用例一起跑（51 例）也仍然全绿——桩只做了纯增量改动（多了 `query()` 访问器）。
  *没有验证的：* 两个真实端点一次都没连过（本机到 `platform.openai.com` 与 `ai.google.dev` 都不同：一个
  403、一个超时），所以字段名只到官方 proto／官方 SDK 生成类型这一层。
- **2.3 更好的编辑** —— `done`，作为 2.5.4。`edits: [...]` 是一次审批、一次写入和一份差异；一个匹配不上、匹配两次或互相重叠的块会让整个改动被拒绝，而匹配不上时会带着文件里它本该在的位置周围那些行回来。
  *验收已满足：* 一次审批显示所有块，而部分应用的补丁不可能发生。
- **2.4 子代理调优** —— `done`。一个角色可以被钉到自己的**模型**与**思考档位**上：配置里的
  `"subAgents": {"explore": {"model": …, "reasoning": …}}`、命令行 `--subagent-model explore=…` 与
  `--subagent-reasoning explore=…`（可重复）、环境变量 `CCJ_SUBAGENT_<角色>_MODEL` / `_REASONING`。没点名
  的角色跟随主对话，而钉住只换这两栏：温度、上限、工具集、审批者、端点与钥匙一律不动——一次委派不是另一个
  提供方。**一次委派自己花了多少**现在写在报告里（`USAGE: <in> in / <out> out / <cached> cached / <n> model
  turns`），有数字才写、钉了别的模型才点名；而任务卡不再是一串参数 JSON，而是「角色：任务首行」。递归仍然
  在构造上不可能（子代理的注册表里没有 `task`）。
  *验收已满足：* 脚本化提供方在 `Request.model()` 里**真的**收到了钉住的那个模型，未钉的角色仍收到主对话的
  模型；档位同理，且换模型时温度与上限不变；花费行里的数字与 `UsageTally` 逐字段一致、没有数字时不写；卡片
  文本用真注册表跑出来。
- **2.5 原生 Windows** —— `doing`。**机制那一半就位，验收那一半没有。** 跑命令的那个程序现在是可配置的
  （`config.json` 的 `"shell"`、`--shell`、`CCJ_SHELL`；不配置时 POSIX 上是 `/bin/bash`，Windows 上是
  `%COMSPEC%` 或 `cmd.exe`），参数形状按程序名决定（`cmd` 收到 `/c`，`powershell`/`pwsh` 收到
  `-NoProfile -Command`，其余 `-lc`），`bash` 工具与编辑后检查共用同一个答案；仓库根多了一个 `ccj.cmd`
  启动器（与 `ccj` 同构：jar 不在时先构建，退出码 75 时重启）。顺路修掉一个真 bug：**起不来的 shell 此前
  被报成「超时」**（两者共用 `finished=false`），于是一个配置错误看起来像一次卡住。
  *验收未满足：* 「一个回合在 Windows 上不用 WSL 跑起来」——本机与 CI 都没有 Windows，所以这一条**没有**被
  证明。本机上真的跑出来的只有：命令确实交给了配置里的那个程序、参数形状按名字分派、shell 不存在时的消息
  点名了三种改法、没配置时与从前逐字相同（自建的可执行文件记录了自己收到的 argv）。真 Windows 上的行为、
  `ccj.cmd` 本身、以及 `chcp 65001` 那一行都只是推算。**4.6 是这一项的收尾。**

## Phase 2.5 —— 围绕循环的循环

**为什么在这里。** Phase 2 回答「它能做什么」；这里回答「为什么用它比本该的更费劲」。下面每一项都来自使用这个工具、撞上摩擦，排序依据是人最先感觉到什么，而不是造什么最有意思。

| # | 是什么 | 为什么排在前 | 状态 |
|---|---|---|---|
| 2.5.1 | **编辑之后自动跑一项检查。** 配置文件里的 `{"checks": [{"glob": "**/*.java", "command": "mvn -q -o -DskipTests compile"}]}`：第一条 glob 与被编辑路径匹配的检查在 `edit`/`write` 调用内部运行，它的判定——通过时一行，失败时有界的摘录——被追加到工具结果 | 同上 | `done` |
| 2.5.2 | **权限规则，而不是一个布尔值。** `approvals.json`（按项目为键，位于应用 home 下），带匹配某个工具、某条精确命令或由尾部 ` *` 放宽的命令、或某个路径 glob 的允许与拒绝规则——外加提示上的**本次会话允许**。这个提示过去只有两个答案：允许一次，或本次会话全部允许 | 同上 | `done` |
| 2.5.3 | **消息排队而不是 409。** 回合运行期间发出的消息在它后面等待，输入框说明有多少条在等，每条排队消息都作为自己的回合运行。中止会丢掉队列并说明丢了几条 | 同上 | `done` |

**2.5.1 的实际实现**，在 `core/Checks` + `tool/PostEditCheck` 里，通过 `tool/ProcessRunner`（从 `BashTool` 中抽出，这也是它那十一个测试成为那次重构的回归网的原因）与 `bash` 共用进程管道。用四种方式设上界，好让它能在每次编辑时运行：每次编辑一项检查、4 KiB 的报告、每项检查一个会杀掉进程树的超时，以及在编辑失败或回合被中止之后完全不跑。第三件事来自拿它跑这个仓库，而不是来自写它：glob 决定检查*何时*运行，而不是决定命令看的是什么，所以 `mvn compile` 会对项目根目录下一个它从未编译过的文件报出成功。通过的那一行因此是 `exit 0` 而不是「clean」，这个警告在 `Checks` 的 javadoc、README 和 SECURITY.md 里。测试钉住了两件否则会成为 bug 的事：检查绝不会为会话工作目录之外的文件运行；以 `**/` 开头的模式在项目根目录下同样匹配——仅靠 `PathMatcher` 做不到这一点，而一项从不悄悄触发的检查看起来和一项无事可报的检查一模一样。

**2.5.2 的实际实现。** `Approver` 变成了 `ApprovalAnswer approve(ApprovalRequest)`——在一个结构化请求（工具、命令、路径，以及给提示用的散文）上给出四个答案——因为一个布尔值说不出「就这一个，不是所有」，而两个字符串无法在不匹配散文的情况下被规则匹配。`RuleApprover` 让规则先于正在看着的那个人作答，两个前端都学会了这四个答案：浏览器的提示有四个按钮，终端的提示接受 `y`/`s`/`a`/n。顺路测出：两个只有测试能抓到、读多少遍代码都抓不到的 bug——为一条含有 `>` 的命令记住的规则永远匹配不上它（元字符规则被用在了精确比较上，而精确比较里没有任何东西能被放宽），以及用户给出的第一条规则会把 `UnsupportedOperationException` 抛进工具调用，因为空的规则文件是个不可变 map，于是「从现在起允许」在第一次使用时静默地什么都没做。两者现在都被测试钉住，而第二个正是那条路径上第三个测试存在的原因：它前面那两个测试都从已经含有一个项目的文件开始。

**2.5 全部落地，而且每一项都是先测量再写的。** 这一批的顺序不是随意的——**2.5.2** 必须在 **2.5.6** 之前，因为一个服务器的工具必须一到就知道哪些规则适用于它们（`mcp__<server>__<tool>` 这个名字形状就是那条规则的落点）。逐项的落地方式、测到过什么、以及每次真机运行改掉的判断，都在 [CHANGELOG.md](CHANGELOG.md) 里；这里只留一句：其中四项（自动压缩的重试距离、多块 `edit` 的块顺序、`write` 等待审批期间文件被改、以及手写配置存不了）是**只在真机或真测试上才显形**的，读多少遍代码都读不出来。

**随之而来的决定，是记录下来而不是以后才发现。** 一条检查命令就是一条命令，而 [CONVENTIONS](CONVENTIONS.md) 说审批是任何会执行的东西的唯一护栏。这条命令是用户写进自己配置文件里的，这和把它写进 `CCJ.md` 或直接敲出来是同一件事——所以它不经提示就运行，而这是对审批模型的一次刻意放宽，并在 [SECURITY.md](../SECURITY.md) 里作为一次放宽写明。它不可以做的是变成一条通用逃生口：这个钩子用会话的工作目录运行那条配置好的命令，仅此而已。2.5.2 落地了，这个豁免**没有**随之消失——`PostEditCheck` 里没有任何审批者，编辑后检查仍然是一条配置好的命令直接跑。这一处是错的，记在这里而不是悄悄删掉：要么它保持为一次写明的放宽（现状，SECURITY.md 就是这么写的），要么它变成一条普通的允许规则——那是 2.6.10。

- **3.3 不会漂移的文档** —— `done`，用的是**检查**而不是生成（理由见 4.4）。新的
  `docs/DocsConsistencyTest` 拿发布出去的字节做两件断言：`docs/USAGE.md` 的「用法」一节必须逐字等于
  `CliOptions.usage()` 打印出来的东西；「工具」那张表里的工具、顺序、参数名、以及哪个参数带 `?`，必须与
  每个工具自己的 `parametersJson()` 一致（「可选」问的是 schema 的 `required`，所以那个问号也是一个被检查
  的主张）。它第一次运行就抓到一处真的不精确：README 把 `old_string`/`new_string` 写成了必填，而 schema
  里它们不是——因为 `edit` 要么给这一对、要么给 `edits`，schema 表达不了这种「二选一」，而表格原来在悄悄
  替它做主。

## Phase 4 —— 长期：让它成为**你**的代理，而不是又一个代理

**先说清楚什么不是差异化。** 2026-09 挨个核过四家的官方文档（Claude Code、Codex、Aider、Cline）之后，这条
必须写在最前面：下面这些**主流都有**，把它们当卖点就是 Phase 0 定义的那种「无法核验的主张」——

| 常见的卖点 | 现状 |
|---|---|
| 检查点与回退 | Claude Code 每回合一个检查点、保留 100 个、`/rewind`；Cline 同义 |
| 细粒度权限规则（allow/ask/deny、通配、按仓库持久化、面板） | Claude Code 的 `/permissions` 比这里的 `approvals.json` 更全 |
| 沙箱 | 主流有（Claude Code 的 sandboxing、Codex 的 sandbox/execpolicy）；这里**刻意没有** |
| 编辑后自动跑检查 | Aider 默认 lint+test、Claude Code 的 PostToolUse hook |
| 网页 / 手机端 | Claude Code 有 web 与手机 App；Cline 有桌面 App 与 telegram/slack 接入 |
| 花费上限 | Claude Code 的 `--max-budget-usd` 与 workspace spend limit；Aider 的 `/cost` |

**也不能当卖点的两件事**：主模型从不看图像（独立视觉模型写文本描述——这是绕开限制的取舍，能力上更弱），
以及中文单语界面（这是事实）。

**真正核到「别家官方文档里找不到」的只有三条**，而这个阶段的每一件事都必须落在这三条上，否则它只是在
重做一件别处已经做得更好的事：

1. **零密钥跑得起来。** `--demo` 自带一个脚本化提供方：不需要账号、不需要网络、不需要 API key，就能把一个
   回合、工具调用、审批提示完整走一遍。四家的文档都要求账号或自备一个 OpenAI 兼容端点。
2. **一个 fat jar 同时是 CLI 和网页控制台。** 没有前端构建产物、没有安装器、没有账号、没有云：`java -jar
   ccj.jar` 之后手机和桌面说的是**同一份本地文件**。
3. **每条主张都带着它的测量结果。** [CHANGELOG](CHANGELOG.md) 里每个条目都写着测到了什么、代价是什么、
   什么**没有**验证；「用起来才发现」是这个项目最主要的功能来源（Phase 2.6 整批都是这么来的）。

Phase 4 因此不是「加功能」，是**把这三条从品格变成可以用的东西**，并把「这台机器上验证不了」的部分逐个
变成 CI 能验证的事实。

### 4.0 把差异与代价写成一份能给别人看的东西 —— `todo`

**是什么。** 一份 `docs/SHAPE.md`（或 README 的一节）：上面那张表照抄进去，加上「不做沙箱意味着什么」
（审批是唯一的护栏，`--yolo` 会拿掉它）、「不换算货币意味着什么」（token 是事实，价目表是假设）、以及
「一个下午能读完」这条维护性主张的**数字**（当前行数、文件数、依赖数）。
**为什么。** 一份诚实的能力对照表比一句「更快更轻」值钱：它同时是给陌生人的说明、给未来的我的备忘，和
issue 少一半的原因（3.0 的免责声明的完整版）。
*验收：* 表里每一行要么有官方文档链接，要么写着「未核实」；「一个下午能读完」旁边有当前的实测数字。

### 4.1 收据：一个回合结束时能核对的东西 —— `todo`

**是什么。** `/receipt`（终端）与网页上的一次点击，给出这一轮的**收据**：改动了哪些文件（来自检查点）、
跑了哪些命令与它们的退出码（来自工具结果）、花了多少 token（来自账本）、以及——这一条是重点——**哪些事
没有验证**（没有跑检查的编辑、被拒绝的调用、被截断的输出、被压缩掉的上下文）。可复制成纯文本。
**为什么。** 「每条主张带着它的测量结果」现在只活在提交信息与 CHANGELOG 里，也就是只活在**我**的流程里。
把它做成产品的一部分，是这三条差异里最不可能被抄走的一条：它要求工具自己承认它不知道什么。
*验收：* 一个跑了工具、改了文件、用过子代理的回合，收据里的文件清单与 `GET /api/undo` 的预览一致、token
与账本一致、命令与退出码与转录一致；一个只有对话的回合，收据明说「没有改动，没有命令，没有验证」。

### 4.2 可携带的会话 —— `todo`

**是什么。** `ccj --export <id>` 与网页上的一个按钮：把一个会话导出成**一份自包含的文件**（markdown 或单个
HTML），含对话、工具调用与结果、图片的缩略图、以及账本。导出**绝不改动原文件**，也不联网。
**为什么。** 主流代理的会话在云上、按账号走；这里的会话是你的文件——但一个 JSONL 不是能给人看的东西。
导出让「本地优先」变成一件可以拿在手上的事（贴进 issue、发给同事、三年后还能打开）。
*验收：* 导出一个用过图片与子代理的会话，文件在**断网**的浏览器里能打开并读得懂；再导一次字节相同（除时间
戳外）；原会话文件与附件目录的 (路径, 大小, mtime) 快照在导出前后完全一致。

### 4.3 把会话带到手机上 —— `todo`

**是什么。** 终端启动横幅里加一个 **ASCII 二维码**，编码当前那个带 token 的 URL（手机扫一下就进来了）；
网页加一个最小的 manifest，让它能「添加到主屏」。
**为什么。** 这是第 2 条差异（一个 jar、同一份本地文件、手机与桌面同权）唯一还差的一步：现在需要人肉把
`http://100.64.0.1:6767/?token=…` 敲进手机。二维码是**零依赖**的（几十行编码器 + 一张纠错表），而它的
测试可以是对着规范向量逐位比对——这正是这个项目喜欢的形状。
*验收：* 用手机扫终端里打出来的那个码能直接打开页面并发一条消息；编码器对至少两组已知输入产出规范里
指定的矩阵；`--host 127.0.0.1` 时**不**打印二维码（码里的地址在那台手机上根本走不通，打出来是骗人）。

### 4.4 不会漂移的文档（3.3 的落地形态） —— `todo`

**是什么。** 让「用法表、工具表、配置表」不再是手抄：要么从代码生成，要么由测试**逐字比对**——哪个更
便宜就选哪个，但必须有一个会失败的东西。`docs/USAGE.md` 里那一份 `--help` 就是 `CliOptions.usage()` 的逐字
副本，而抄错一次没人会知道。
**为什么。** 「README 的能力表每一行都是一个主张」（[CONVENTIONS](CONVENTIONS.md)）现在靠人评；而人评是
这个仓库里唯一没有机器守着的一条约定。
*验收：* 改一次 `usage()` 却不同步 README，`./mvnw test` 失败，并且失败消息说出该改哪一段。

### 4.5 开销账本：记录这个工具自己有多贵 —— `todo`

**是什么。** 把三类开销**量出来并记下来**（启动到能收下第一条消息、每个回合固定发出去的前缀——系统提示
加工具 schema、以及一条会话被打开与列表的代价），并修掉已经量出来的那一处：侧栏每次列会话都会把变更过的
会话文件**整个解码**，而它只需要第一行；正在写的那条会话每个回合都被整份重解析一次。
**为什么。** 这是一个不到三千行核心的代理，它的一个卖点是「小到能读完」；而小如果不体现在延迟上，就只是
一种审美。数字进 CHANGELOG 的格式与 Phase 2.5 用的一样。
*验收：* 启动与每回合前缀有数字（本机 + CI 平台各一次），并且**每一处修复都带着它修前的数字**。

### 4.6 Windows 的真相 —— `todo`

**是什么。** 2.5 把 shell 做成了可配置的，但**没有任何人**在真 Windows 上跑过一次。这里要的是证据：CI 加
一个 `windows-latest` 的作业，只跑那些不与 POSIX 绑定的测试（`Config`、`Json`、`MessageCodec`、`Provider`
的桩测试、`Tools` 的 schema 测试……），把必须 POSIX 的测试明确标出来（`@EnabledOnOs` 或一个具名的
tag），而不是让它们静默跳过。
**为什么。** 路线图里凡是「在这台机器上验证不了」的条目，写的都是同一句话：CI 是唯一的证据。2.5 目前是
一个**没被验证的声明**，而不被验证的声明就是 Phase 0 要消灭的那种东西。
*验收：* 一个 `windows-latest` 的作业真的跑起来并通过；它的日志里能看到「一个回合跑起来了，shell 来自
配置」；POSIX-only 的测试是被**具名**排除的，而不是悄悄跳过。

### 4.8 `AgentHub` 剩下的那一半 —— `todo`

**是什么。** 这个类从 2811 行降到了 2428 行，而它仍然是一个下午读不完的东西。剩下的是三块互不相同的东西挤
在一起：**回合的执行**（`runTurn`、`newLoop`、`registryFor`、`drain`、`autoCompact`、几个 `abort`）、
**那两个内部类 `Conversation` 与 `WebListener`**（约 270 行，握着会话、锁、事件与审批之间的胶水），以及
**表单往返**（providers / workspaces / settings 三节各一百到三百行）。
**为什么排在最后。** 这三块不像 `EventStream`/`ApprovalDesk`/`SettingsFiles` 那样各自持有自己的状态——它们
**共享** AgentHub 的字段，所以搬走每一步都要先做一次设计（哪些状态跟着走、哪些用回调、谁持有会话），而设计
错的代价是「多了一层转发壳」，那比一个大类更糟。所以它是一件需要想清楚再做的事，不是一次体力活。
*验收：* 三个文件里每一个都在 800 行以内，或者一份写下来的「为什么它就该这么大」；无论哪一种，测试全绿，
且 `Conversation` 与 `WebListener` 之间不再需要经过 AgentHub 的字段互相说话。

### 4.7 附件：把图片那条路推广到别的文件 —— `todo`（可能不做）

**是什么。** 现在「一个文件进入对话」的形状只有图片有：独立模型 → 文本描述 → 描述进对话，文件留在会话
旁边。日志、PDF、一张巨大的表格都符合同一个形状。
**为什么排最后。** 它扩大的是能力，而能力恰恰是这个项目最不缺的东西；三条差异一条都不在这一项上。真做
的理由只有一个：**用起来的时候确实需要它**（Phase 2.6 的规矩）。
*验收：* 上传一个非图片文件，主机型收到的是描述而不是字节；没有配置视觉模型时给出的拒绝与图片那条完全
同形。

## 不打算做

写下来，好让它不再被反复争论：

- **一个沙箱。** 审批就是模型，README 也是这么说的。基于容器的沙箱是另一个产品，有另一套信任故事。
- **一个多用户服务器。** 没有账号、没有租户、没有按用户的会话。网页 UI 是给启动它的那个人的控制台。
- **一个插件市场。** MCP（2.1）就是可扩展性的答案。
- **用货币表示的成本。** 一张价目表是一种不打招呼就会变的假设；token 计数和缓存命中率才是事实。
- **子代理互相交谈。** 它们向主代理汇报，主代理是唯一掌握全貌的参与者。
- **把搜索写进核心。** 搜索需要一把第三方密钥和一个供应商选择，而这个项目的卖点之一是零密钥就能跑
  （`--demo` 连模型都不需要）。提供方自带的服务端搜索更糟：请求由**他们的**服务器发出，绕开本地审批，
  与「审批是任何会出网的东西的唯一防线」直接冲突。搜索走 MCP（2.6.9），核心只负责给出那条路。
- **原生镜像（native image）。** 它与基于反射的 Jackson 配置冲突，而那个冲突换来的是一个为了省几百毫秒
  启动时间、却更难调试的构建。3.2 因此只在 fat jar 与 `jpackage` 之间做决定。
- **云端的会话同步。** 会话是这台机器上的文件，这是第 2 条差异本身。想换机器就把文件拷过去；一个账号加
  一个后端会把「你的文件」变成「他们的服务」。
- **语音输入。** 它需要一套本机没有的模型与依赖，而键盘就在你手边。

## 一项工作如何完成

一次一项，按上面的顺序，沿用现有工作已经有的形状：

1. **测试先行。** 如果这项是个 bug，那个没有修复就失败的测试就是交付物的另一半。如果是个功能，上面那行验收就是测试。
2. **满足它的最小改动。** 这个项目的价值在于一个下午就能读完；一个牺牲了这一点的聪明修法是一笔坏交易。
3. **文档随改动一起。** README、`docs/`，以及代码旁边的注释。当某个机制被移除时，它的描述也一起走——一段声称某个已不存在的护栏的陈旧文字比没有更糟，因为下一个读者会信它。
4. **说明测量到了什么。** 「测量：第二个对话删掉了第一个对话的文件」抵得上十段推理，现有文档就是这么写的。
5. **报告什么没有跑。** 一个无法在这台机器上验证的改动要说明这一点，在提交信息里，也在给请求它的人的回复里。

关于与之配套的代码层面规则，见 [CONVENTIONS.md](CONVENTIONS.md)。
